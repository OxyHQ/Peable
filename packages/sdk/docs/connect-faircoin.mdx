# FairCoin sellers

Pay a marketplace's **sellers** in FairCoin, straight to their own wallets —
like Stripe Connect, without anyone ever holding the coins.

You are the **platform**: a Peable merchant. Each seller gets a **connected
account** (`ca_…`) naming the seller's **own** Oxy account. No one registers a
key. You create payments on behalf of a seller (`connected_account: 'ca_…'`):
the payer's address derives from the public identity key of the seller's Oxy
account, so the coins go payer → the seller's Peable wallet in one
transaction. You own the payment
record and receive every webhook for it, each tagged with the seller. Peable
never holds the coins, and neither do you.

```
platform ──create account──────────▶ Peable          (network + the seller's Oxy user id)
platform ──account link────────────▶ Peable ──url──▶ seller
seller (own Oxy session) ──confirms──▶ Peable ──connected_account.updated──▶ platform
platform ──payment intent { connected_account }──▶ Peable ──address from the SELLER's identity key──▶ payer
payer ──FAIR──▶ seller's Peable wallet
Peable ──payment_intent.* { account: 'ca_…' }──▶ platform
```

## 1. Open the seller's FairCoin account

```ts
const seller = await peable.connectedAccounts.create({
  external_ref: store.id, // YOUR id for the seller: the idempotency
  faircoin: { network: 'testnet', oxy_user_id: store.ownerOxyUserId },
});
seller.rails;    // ['faircoin']
seller.faircoin; // { network: 'testnet', status: 'pending', oxy_user_id, registered_at: null }
```

- **`oxy_user_id` is the seller's identity**: the only account that may
  confirm, and the one whose Peable wallet receives. You know who owns the
  store; Peable does not. It cannot change later — a store that changes hands
  gets a new account (a new `external_ref`).
- **Nothing you send decides where the money goes.** There is no key
  parameter: the seller's own Oxy account receives, and only the seller can
  turn it on (step 2).
- **A test credential can only open `testnet`.** A live one can open either.
- **Repeat freely.** The same `external_ref` answers the same `ca_…` (`200`
  instead of `201`). A card seller (`country` + `business_type`) can be given
  FairCoin later by the same call, and a FairCoin seller cards — one seller,
  one `ca_…`, both rails. A different network or Oxy user on an existing
  FairCoin account is a 409.

## 2. Send the seller to confirm

```ts
const link = await peable.connectedAccounts.createAccountLink(seller.id, {
  rail: 'faircoin',
  return_url: 'https://market.example/sell/payments/done',
  refresh_url: 'https://market.example/sell/payments/refresh',
});
redirect(link.url); // Peable's own onboarding page
```

The seller opens it **signed in with Oxy as `oxy_user_id`** and confirms that
FairCoin paid to them goes to that account's Peable wallet. No key is sent.
If the account has no Peable wallet yet, the confirmation is refused with
[`409 faircoin_wallet_missing`](/errors#faircoin_wallet_missing): the seller
creates the wallet in Peable and confirms again.

- **Mint on demand, never store.** A link works once and for an hour. An
  expired or used link sends the seller to your `refresh_url` — mint a fresh
  one there.
- **The link alone opens nothing.** It needs the seller's Oxy session; a
  forwarded link is useless to anyone else.
- **`return_url` proves nothing.** Wait for the event (step 3) or read the
  account.

## 3. Learn that the seller is ready

```ts
if (event.type === 'connected_account.updated') {
  const seller = event.data.object; // ConnectedAccount
  if (seller.faircoin?.status === 'active') enableFaircoinCheckout(seller.external_ref);
}
```

The event is committed in the same transaction as the confirmation, so it is
never lost and never early. `payable` on the same object is about **card**
settlements and says nothing about FairCoin.

## 4. Take a payment for a seller

```ts
const intent = await peable.paymentIntents.create(
  {
    amount: '250000000',            // 2.5 FAIR
    rail: 'faircoin',
    network: 'testnet',             // must be the SELLER's network
    connected_account: seller.id,
    metadata: { order_id: order.id },
  },
  { idempotencyKey: `order:${order.id}` },
);
intent.faircoin.address;  // in the SELLER's Peable wallet
intent.connected_account; // seller.id
```

or a Checkout Session with the same `connected_account`. A `FAIR` session
pays the seller in FairCoin. A fiat session offers the payer your card
methods and FairCoin: a FairCoin choice is an on-behalf payment to the
seller, quoted in FAIR ([FairCoin on every order](/faircoin#the-quote)),
and a card payment is your own charge, which you settle to the seller with a
[transfer](/connect#card-sellers). Refusals to handle:

| Answer | When |
|---|---|
| `409 account_not_ready` | The seller has no FairCoin account or has not confirmed |
| `400` | A card payment with `connected_account` (card sellers are paid with [destination charges](/connect#charges-and-fees)), or a network other than the seller's |
| `404` | The `ca_…` is not one of your sellers |
| `400 idempotency_error` | An `Idempotency-Key` replayed for a different seller, amount or rail |

`peable.paymentIntents.list({ connected_account: seller.id })` lists one
seller's payments.

## 5. Webhooks

Every event about an on-behalf payment comes to **your** endpoint, with the
seller on the envelope:

```ts
const event = peable.webhooks.constructEvent(rawBody, signature, secret);
if (event.account) {
  // a payment for seller event.account (also event.data.object.connected_account)
}
```

`event.account` is absent on events about your own payments.

### Never cancel a paid order on your own clock

`expires_at` applies only while the payer has not paid. Once the payer's
wallet reports the broadcast, the intent is `processing` until it is
`succeeded`, and it **never expires**; `can_expire` says which. Release the
seller's stock only on `payment_intent.canceled`. To stop a checkout early,
`paymentIntents.cancel(id)`: `payment_intent_unexpected_state` means the payer
got there first — the order is paid.

One case is outside Peable's sight: a payer who pays the address from an
external wallet **without** the transaction being reported. The intent can
then expire with the coins already in the seller's wallet. The money is safe —
it is the seller's — and the order is resolved between you, the seller and the
payer.

## Refunds and fees

A FairCoin refund is a payment from the seller's wallet back to the payer.
Peable never held the coins and cannot return them; `refunds.create` refuses
the FairCoin rail, and your platform's policy decides what the seller pays
back.

Platform fees on FairCoin payments are not offered, on a `FAIR` order or a
fiat one: the coins never pass through you, so a fee would need a second
movement of money. The seller receives the whole amount, and
`application_fee_amount` on a FairCoin payment is a 400. Take your commission
on card payments.

## Checklist

- [ ] On store creation (or when the owner opts in):
      `connectedAccounts.create({ external_ref: storeId, faircoin: { network, oxy_user_id } })`.
- [ ] Seller settings → "Get paid in FairCoin" →
      `connectedAccounts.createAccountLink(id, { rail: 'faircoin', … })` → redirect.
- [ ] On `connected_account.updated` with `faircoin.status === 'active'`,
      enable FairCoin at that store's checkout.
- [ ] One payment or Checkout Session per seller group, with
      `connected_account` (and `rail: 'faircoin'` on a PaymentIntent).
- [ ] Fulfil on `payment_intent.succeeded`; release stock only on
      `payment_intent.canceled`.
- [ ] Testnet end to end before anything else.
